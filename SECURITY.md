# Безопасность

Petri v0.3 — экспериментальный код, не прошедший независимый security audit. Успешный CI не доказывает отсутствие уязвимостей. Не используйте Petri как единственный барьер для заведомо враждебных workloads или чувствительных хостов.

Текущие границы и известные ограничения описаны в [модели угроз и ADR](docs/decisions.md), [внутреннем review](docs/security-review.md) и [статусе](docs/status.md). Linux sandbox разделяет ядро хоста; нет полных cgroup/disk/log quotas, готового Vault и VM/WSL2 backend на других ОС.

## Сообщить об уязвимости

Если в разделе **Security → Advisories → Report a vulnerability** репозитория доступна приватная отправка, используйте её. Наличие этой возможности пока не подтверждено данной документацией. Иначе сначала свяжитесь с maintainer приватно через доступный вам проверенный канал; адрес электронной почты или иной контакт здесь не выдумывается.

Если приватного канала нет, можно создать публичный issue с просьбой предоставить канал для security report, **без деталей эксплуатации, секретов и пользовательских данных**. Не публикуйте подробный PoC до согласования безопасного раскрытия.

В приватном отчёте укажите commit/version, ОС и kernel, конфигурацию запуска, ожидаемую границу изоляции, фактический результат и минимальное воспроизведение на одноразовых данных. Удалите credentials, приватные исходники и идентифицирующие журналы. Не проверяйте уязвимость на чужих системах.

## Исправления

Пока стабильных поддерживаемых релизных веток нет. Исправления готовятся для актуальной разработки, а поддержка старых версий и сроки ответа отдельно не обещаны. Security fix должен включать регрессионную проверку и обновление модели угроз/ограничений. Потенциально раскрытый credential отзывается у провайдера: удаление файла или маскирование логов не отзывает доступ.
