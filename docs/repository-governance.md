# Ветки и правила репозитория

Редакция: 2026-10-26. Репозиторий: [QahNaaRlN/Petri](https://github.com/QahNaaRlN/Petri).

## Целевая конфигурация

| Объект | Правило |
| --- | --- |
| `main` | Ветка по умолчанию и защищённая база для изменений; заменяет `master`. |
| `feat/*`, `fix/*`, `docs/*`, `chore/*` | Короткоживущие рабочие ветки. Изменения поступают через PR в `main`. |
| `dev` / `develop` | Отдельная постоянная ветка не нужна. |
| `release/*` | Создаётся только при реальной необходимости сопровождать релиз; сейчас создавать пустую ветку не требуется. Перед использованием включается аналогичная защита. |
| Merge | Разрешён только squash merge; обычный merge commit и rebase merge отключены. Рабочая ветка может удаляться после слияния. |

Для `main` обязательны PR, успешные пять проверок ниже, актуальность ветки относительно базы и разрешение всех review conversations. Force push и удаление `main` запрещены; правила применяются также к администраторам. Прямой push не является штатным способом внести изменения.

Проект пока ведётся одним владельцем: обязательное независимое approval не устанавливается, чтобы не блокировать работу единственного maintainer. Это не отменяет PR, CI и проверку изменений самим владельцем. При появлении команды число обязательных approvals пересматривается отдельно.

| Обязательная проверка CI | Что проверяет |
| --- | --- |
| `Build and portable tests (ubuntu-24.04)` | Linux host-side tests, fmt/clippy и release build |
| `Build and portable tests (macos-14)` | Переносимые host-side tests и build; не macOS VM isolation |
| `Build and portable tests (windows-2022)` | Переносимые host-side tests и build; не WSL2 isolation |
| `Native Linux isolation (required; no skipped success)` | Настоящий Linux namespace/rootfs/network E2E |
| `Dependency vulnerability audit` | Проверка зависимостей по RustSec |

При переименовании CI job сначала согласуется соответствующее required check: устаревшее имя может навсегда заблокировать merge. Изменения CI и правил защиты проходят проверку, не обходятся фиктивными успешными статусами.

## Применение GitHub settings с локальной авторизацией

Подготовлен [scripts/configure_github.py](../scripts/configure_github.py). По умолчанию он показывает план без изменения репозитория (`--dry-run` — явный эквивалент); применение требует `--apply` и административных прав локального GitHub CLI. Используйте Python 3.10+ и `gh`, авторизованный владельцем:

```sh
gh auth login
python scripts/configure_github.py
python scripts/configure_github.py --apply
python scripts/configure_github.py --verify
```

Предпочтителен fine-grained PAT с доступом **только к `QahNaaRlN/Petri`** и разрешениями **Administration: Read and write**, **Contents: Read**, **Pull requests: Read and write**: последние нужны для проверки refs и переноса открытых PR с `master` на `main`. Альтернатива для classic PAT — scope `repo`. Это разрешения токена локального CLI, а не просьба передать токен ассистенту. Не вставляйте токен в чат, командную строку с сохраняемой историей, исходники или коммит; используйте интерактивный `gh auth login` и штатное защищённое хранилище GitHub CLI. Сам скрипт не выполняет login и не читает значения токенов.

Перед применением просмотрите dry-run. `--verify` только читает настройки и возвращает ошибку при несовпадении; `--report PATH` сохраняет очищенный JSON-отчёт. Скрипт ограничен указанным репозиторием на github.com, не удаляет `master`, не переписывает историю и не сливает PR. После применения он перечитывает default branch, merge policy и защиту. Если GitHub возвращает 401/403, процесс останавливается с объяснением прав; частично выполненное применение не считается успехом и требует проверки снимка. Не отключайте CI и не заменяйте результат текстовым отчётом об успехе.

## Локальная копия Windows

Желаемый путь: `D:\PersonalProjects\Petri`. Создание файлов в облачной Linux-среде не подтверждает клонирование на личном компьютере Windows. Подготовлен безопасный [scripts/clone-windows.ps1](../scripts/clone-windows.ps1): по умолчанию выбирает этот путь и ветку реализации, проверяет существующий каталог, origin и чистоту рабочего дерева. До слияния PR #1 ручные команды для нового каталога в PowerShell:

```powershell
New-Item -ItemType Directory -Force 'D:\PersonalProjects' | Out-Null
git clone --branch feat/petri-v0.3 https://github.com/QahNaaRlN/Petri.git 'D:\PersonalProjects\Petri'
git -C 'D:\PersonalProjects\Petri' status
```

Если каталог уже существует, не удаляйте и не сбрасывайте его: сначала проверьте `git status`, origin и текущую ветку. Стандартный `git clone` на Windows требует установленного Git; это инструмент разработки репозитория, а не runtime-зависимость самого Petri.

Скрипт Windows не рассчитан на одновременное редактирование каталога другим процессом. Он перепроверяет origin, ветку и чистоту после fetch и перед ff-only merge, однако не может транзакционно заблокировать произвольные внешние операции Git.
